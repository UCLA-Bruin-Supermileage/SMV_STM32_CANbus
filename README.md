# SMV_STM32_CANbus
Bruin Racing Supermileage CANbus Library

This library is compatible with any CAN-enabled STM32F4XX device, but has only been validated for the STM32F446RE. The library expects that the target device has an built-in CAN controller. Arduino libraries for the RP2040 Adafruit CAN Feather, Teensy4, and ESP32 are available [here](https://github.com/UCLA-Bruin-Supermileage/UCLA-SMV-CAN/tree/main). The assumption is that no boards will continue to use these libraries (except the DAQ board), and thus these libraries are no longer maintained (but are backwards compatible with this one). Note that both libraries are fixed at 500 kbps and will not function together if the bit rates are manually changed to differing values.

## Installation

Before you do anything, you will need to initialize your IOC (the .ioc file) to the correct specs. Contact a DAQ lead if you are having trouble with this.

#### Choose Your Pins
Activate your CAN pins in the visual IOC pin selector, and then confirm that the appropriate CAN controller is activated. Don't set any parameters, since the library will do it for you.

#### Clock Configuration
Switch to the Clock Configuration tab and set the following parameters: 
* Switch PLL Source Mux to HSE 
* Set HCLK to 72 MHz

#### Activate Interrupts
Activate the RX0 interrupt in NVIC

#### Add Library Files and User-Defined Functions

Put all `.h` files under /Core/Inc, and put `smv_canbus.c` under /Core/Src. For reference usage, `SMV_CAN_Example_Sender_Receiver` is an example that utilizes the CANbus library's sending, receiving, and filtering functionality.

You will also need to add `HAL_CAN_RxFifo0MsgPendingCallback` (covered in Receiving Data section) and `Error_Handler` into your `main.c` file as defined in our example, `SMV_CAN_Example_Sender_Receiver`. If anything is autogenerated already for you, replace it with what we have defined.

### Initialization

In the functions below, replace anything in all caps with the corresponding enumerator for your board and message type. Enumerators are in `smv_board_enums.h`.

First, remove the function call to `MX_CAN1_Init()`. You're free to remove the function declaration and definition as well, since our library init function replaces it. 

Initialize a new CAN object with:

```
#include "smv_canbus.h"
...
CAN_HandleTypeDef hcan1; // generated by IOC
CANBUS can1;
...
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
...
can1 = CAN_new();
can.init(&can1, YOUR_BOARD_ID, &hcan1); // reference main.c for an example
can.begin(&can1); // because this is C, all methods require a pointer to the object itself
```

## Sending Messages on the CANbus
Our library simplifies the sending process to just a single function 
```
can.send(&can, YOUR_DATA, TYPE_OF_DATA);
```
A comprehensive class description and list of methods are found under `smv_canbus.h`, inside the struct definition for `CANBUS`. Because this is C, this is technically not a class, but for your use that is not relevant.

**NOTE:** You must have an interval between each send. Below is an example implementation of a basic non-blocking send delay:
```
uint32_t timer = HAL_GetTick();
...
while (1)
{
   if ((HAL_GetTick() - timer)> CAN_SEND_DELAY){ //you must define the delay yourself
      timer = HAL_GetTick();
      can1.send(&can1, 0, Horn);
      can1.send(&can1, 1, Wipers);
  }
}
```
## Receiving Data

SMV's CANbus library is designed to use interrupts to recognize and process new incoming messages. To activate this functionality, you'll need to drop this callback function into your main.c file:

```
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *CanHandle)

{
    /* Get RX message from FIFO0 and fill the data on the related FIFO0 user declared header
       (RxHeaderFIFO0) and table (RxDataFIFO0) */
    if (HAL_CAN_GetRxMessage(CanHandle, CAN_RX_FIFO0, &(can1.RxHeaderFIFO0), can1.RxDataFIFO0) != HAL_OK)
    {
        /* Reception Error */
       Error_Handler();
    }else{
    	CAN_Interrupt_Helper(&can1);
      if (can1.getHardwareRaw(&can1) == BOARD_NAME && can1.getDataTypeRaw(&can1) == TYPE_NAME){
        can_read [0] = can1.getData(&can1);
      }
    }
}
```

## Filtering Senders and Types

In order to minimize the computational time spent on processing interrupt callbacks, users of this library have the option to define which boards and data types they would like to trigger an interrupt:

```
can1 = CAN_new(); // construct a CAN object
can1.init(&can1, YOUR_BOARD_ID, &hcan1); // methods require pointers to self because C has no "this" pointer
...
can1.addFilterDeviceData(&can1, SENDER_BOARD_ID, DATA_ID); //Add all filters before running the begin function
can1.addFilterDevice(&can1, SENDER_BOARD_ID)
...
can1.begin(&can1);
